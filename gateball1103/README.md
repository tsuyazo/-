# ゲートボール1103準拠カードゲーム（仮）

遊戯王OCGのゲートボール「1103環境」（2011年3月1日施行の制限リスト、2011年8月31日までのカードプール）をベースにしたカードゲームの第1弾データ。
**ルール・カードの性能（数値と効果）・デッキ構成・カード名は参照元（OCG）と同じ。** カード画像はゲームのアーティファクト（非公開）のアセット置き場にだけ置き、このリポジトリには入れていない（`game/card_images.json` はその参照URLの表）。

| ファイル | 内容 |

## データの作り方

- **制限リスト**：2011年3月1日施行のOCGリストを、YGOPro（Fluorohydride/ygopro）の2011年12月時点の `lflist.conf` から取り出した（`tools/lflist_2011_03_ocg.json`、134種）。
- **カードの数値**（レベル・属性・種族・攻守）：ProjectIgnis/BabelCDB の `cards.cdb` から自動で取得。
- **効果**：DB上の現行テキストではなく、**2011年当時（エラッタ前）の性能**で書き直した。例：「増殖するG」は1ターンの回数制限なし、「BF-精鋭のゼピュロス」は回数制限なし、「クリッター」は回数制限なし、「氷結界の龍 ブリューナク」はフィールドのどのカードでも戻せる。
- **ビルド時のチェック**：メイン40〜60枚、エクストラ15枚以下、制限枚数、融合・シンクロ・エクシーズモンスターがエクストラ側にあること。

```sh
cd tools
curl -L -o cards.cdb https://raw.githubusercontent.com/ProjectIgnis/BabelCDB/master/cards.cdb
python3 build.py cards.cdb   # data/ と *.md を作り直す
```

## 注意点・未確定の部分

1. **デッキレシピ**：墓地BF・代行天使（TG天使）・カラクリ・デブリダンディ・クイックダンディ・六武衆の6デッキは、jspeed氏のブログ「くされにっき」のリストをそのまま使う（`tools/apply_jspeed.py`）。1103で使えないカード（禁止・制限超過・2011年9月以降の発売）だけを役割の近いカードに差し替え、差し替えはすべて `decklists.md` と `tools/recipes_meta.json` に記録した。1103のリストがあるのは墓地BFだけ（ISDCS第10回）で、他は近い時期のリスト。ブログにリストが無いラビット・HERO・TGガジェット・暗黒界は、以下の寒波亭のレシピのまま。
   寒波亭のレシピ（4デッキ）：寒波亭の資料室（note）と公式デッキDBに掲載された入賞レシピ。取得した元データは `recipes/raw/`（ブランチ `claude/gateball-recipes-raw`）。代行天使だけは入賞レシピの画像が判読しにくかったため、寒波亭が公式DBに登録した参考レシピ（入賞記録の記載なし）を使っている。TGガジェットは判読できなかった罠2枚を除いた43枚。
1-2. **環境分析**：「直近100大会のベスト8」の全集計はしていない。読めた範囲の大会結果とTier表を使った（詳細は [decks.md](decks.md) §1）。
2. **カードプールの境界**：一部のカード（エクシーズモンスターや後期のテーマカードなど）は、2011年8月31日までに発売されていたかを一次資料で確かめられていない。疑わしいものは採用を避けたが、各大会のカードプール規定と照らし合わせることを推奨。
3. **収録範囲**：10デッキに使う199種だけを移植した。参照元の全カードプールの移植は今後の作業（`limit_list.md` の開発用資料に、未収録の制限カードも載せてある）。
4. **カード名と画像の権利**：カード名・カード画像はKONAMIの著作物。画像は個人で遊ぶための非公開アーティファクトにだけ置いている。一般向けに公開する場合は扱いを見直すこと。

## ゲーム（自動処理デュエル）

- デュエルエンジンに **EDOPro のコア（ocgcore）** の WebAssembly 版（npm `ocgcore-wasm` 0.1.2、MIT）を使い、カードの効果は **ProjectIgnis/CardScripts** の Lua スクリプト（AGPL-3.0）で処理する。ADS → YGOPro → EDOPro と続く「スクリプトでカード効果を処理する」方式。
- ルールはエンジンの「マスタールール2」設定（先攻もドロー、フィールド魔法は場全体で1枚）。
- 2011年当時の性能に合わせて一部スクリプトを差し替えている（`game/scripts/PATCHES.md`）。
- CPU（`src/ai.js`）：
  - 罠・手札誘発は「相手の何に撃つか」で判断する（召喚無効は重要なモンスターに、攻撃反応は強い攻撃に、など）。
  - メインフェイズは、行動の候補をそれぞれ影のデュエルで試し、ターン終了時の盤面が一番良いものを選ぶ（`src/ai_plan.js`）。影のデュエルでは相手は任意の発動をしないので、CPUが相手の伏せや手札を覗くことはない。
  - デッキ別のサーチ先・止めるべきカード・温存するカードは `knowhow/ai_rules.json`（記事から集めたもの）を使う。
  - jspeed氏の助言（`jspeed/advice.json`）から作ったルール（`src/ai.js` の末尾）：ガンナー・グレファーを先出ししない、伏せは3枚まで（墓地BFの先攻は2枚）、目的の無いエンドサイクをしない、トリシューラはメイン2、ブラック・ホールは温存、ブラック・ローズは場を流して得な時だけ、オネストのあるデッキの光属性は殴らない、リクルーターを自分から殴らない、裏守備はトマト・ガンナーで叩く、シエンは魔法罠を止める、ゴッドバードアタックは除去への返し・攻撃された時・相手のエンドフェイズに、謙虚は特殊召喚できるターンに撃たない、六武衆の荒行はバトルフェイズに。
  - 強さの確認は `node bench.mjs`（初期版のCPUとの対戦成績）。
- `game/scripts/` は AGPL-3.0 のため、ゲームを公開・配布する場合はソースの公開などAGPLの条件に従うこと。

```sh
cd game
npm install
npm run build   # index.html を作る（約2MB、エンジンとデータを1ファイルに埋め込み）
npm test        # CPU同士で全組み合わせを対戦させ、決着まで進むかを確認
node stress.mjs 1000   # 1000戦のテストプレイ（CPU同士／ランダムな操作）で不具合の兆候を集める
node bench.mjs 2       # 新しいCPUと初期版のCPUの対戦成績
```
